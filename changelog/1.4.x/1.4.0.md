# 1.4.0 — 2026-09-27

## Added

- **`pixoo_render_html`** ([#25](https://github.com/cyanheads/pixoo-mcp-server/issues/25)) renders an HTML page (full document or body fragment, ≤ 500,000 characters) at the panel size and pushes it: `frames` 1–800, `speed`, `sampling` (`native` | `supersample`), `finish`, `push`, `output`. Uncaught errors, `console.error` output, and blocked URLs return in `pageErrors` (first 20).
- **Virtual clock for HTML frames** (#25): `window.render(t, frame)` runs before each capture with `t = frame / frames`; `requestAnimationFrame`, timers, `Date`, and `performance.now()` advance `speed` ms per frame, and CSS animations are seeked to it, so frames are deterministic.
- **Page defaults** (#25): no body margin, no scrollbars, and a page that paints no background renders on black (unlit). A `window.render` that throws fails `page_error` naming the frame.
- **Isolated headless renderer** ([#24](https://github.com/cyanheads/pixoo-mcp-server/issues/24)): chrome-headless-shell over the DevTools pipe, one browser context per render, no network and no workers, a 30 s deadline (`render_timeout`), and `render_crashed` (retryable). The browser launches on first use and closes after 5 idle minutes and on shutdown.
- **`PIXOO_BROWSER_PATH`** (#24): the browser to use; unset, the newest chrome-headless-shell in Puppeteer's cache (`~/.cache/puppeteer`), and none found fails `browser_unavailable` with the install command. The Docker image ships no browser.
- **`pixoo` page runtime** ([#26](https://github.com/cyanheads/pixoo-mcp-server/issues/26)): every page gets `pixoo.context()`, `pixoo.text`, `pixoo.icon`, `pixoo.palettes`, and `pixoo.size`, drawing text and icons that match `pixoo_compose_scene` pixel for pixel. `bun run build` writes it to `dist/page-runtime.js`.
- **`PIXOO_HTML_ENABLED`** (#25, default `true`): `false` removes `pixoo_render_html` from `tools/list`; a non-boolean value fails startup.
- **`pixoo_design_brief` topic `html` and output `htmlRenderer`** (#25): page-authoring guidance, and whether the renderer is `available`, `disabled`, or `no_browser`, found without launching a browser.
- **GIF playback past 40 frames** ([#31](https://github.com/cyanheads/pixoo-mcp-server/issues/31)): the device downloads one panel-size GIF from a one-shot listener bound to the local address routed to `PIXOO_IP`; it fails `gif_serve_failed` when the device does not request it, or stalls the transfer, for 10 s. Speed rounds to 10 ms.
- **`PIXOO_SERVE_HOST` / `PIXOO_SERVE_PORT`** (#31): the host advertised in the GIF URL and a fixed listener port, for NAT, firewalls, and Docker (see the README's Docker examples).
- **`bun run test:browser`**: the gated real-browser suite, run against `PIXOO_TEST_BROWSER_PATH`; `bun run test` launches no browser.

## Changed

- **`pixoo_compose_scene` `frames` goes to 800, and `pixoo_push_image` gains `maxFrames`** (1–800, default 40) (#31). More than 40 frames play as a device-downloaded GIF, so the device must reach this host.
- **Past 40 frames, the saved GIF is the panel-size GIF** the device downloads (`PIXOO_OUTPUT_DIR` and a failed push's `outputFiles`), not the 8× preview GIF (#31).
- **Past 49 frames at 64 px, the contact-sheet preview samples evenly** (#31): every frame while 1× tiles fit the 512 px sheet (49 at 64 px, 225 at 32, 784 at 16), then frame `floor(k × n / fit)` in tile `k`.
- **`pushed: true` past 40 frames** means the device accepted the play, requested the GIF, and the whole file was handed to the OS to send (#31).

## Fixed

- **A push cancelled during the pacing wait or the channel switch sends no push command** (#31) and fails with the request's abort reason.
